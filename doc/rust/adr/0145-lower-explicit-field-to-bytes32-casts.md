## Historical decision and amendments

Status: Delivered locally, pending integration · 2026-10-05 · rust-backend-v2 · MediaNoxLabs/compact#248 · a83802c8744da9576c4673c4773c13adca2740c2

### Problem

The exact ledger-8 `test-center/test-contracts/bboard.compact` still rejects Rust compilation at line 44 after ADR-0138. Its `instance as Field as Bytes<32>` inside `public_key(...)` lowers to Compact's distinct `field->bytes` expression. The Rust source extractor has no pattern for that node and reports an unsupported circuit expression. Source mutation probes show the cast is the first independent blocker in both `post` and `take_down`; replacing the cast with a `Bytes<32>` default advances each function to later blockers. Three bboard exports remain unassessed.

### Before and after

Before (original source):

```compact
poster = disclose(public_key(local_secret_key(), instance as Field as Bytes<32>));
assert(poster == public_key(local_secret_key(), instance as Field as Bytes<32>), "not current poster");
```

Before (current Rust): `field->bytes` reaches the generic unsupported-expression diagnostic. A cast must encode the field's canonical nonnegative integer in little-endian order, padded with zero bytes, matching `convertFieldToBytes` in the ledger-8 TypeScript runtime.

After (proposed minimal IR):

```json
{"kind":"field_to_bytes32","value":{"kind":"counter_read","field":"instance","index":2}}
```

The exact field index is generated by the compiler. A generated Rust expression should use the pinned midnight-zk `Field::as_le_bytes()` and the existing typed `FixedBytes<32>` primitive. For a canonical field the 32-byte destination always fits; shorter widths require separate range handling and are outside this decision.

### Decision, emitter and runtime

Add one explicit `FieldToBytes32` expression to the private Rust IR and bump its exact version from 12 to 13. Scheme lowers only `field->bytes` length 32, recursively lowering the operand in pure or stateful context. The native renderer requires a Field operand, uses its canonical 32 little-endian bytes, and returns `Bytes<32>`. The recorded renderer may admit only fully typed, ordered/effect-safe shapes it can replay; unsupported nested witness/callee forms remain unavailable. Use the existing midnight-zk `Field` and runtime `FixedBytes<32>`; the runtime CounterSlot read path must use Compact’s cached equality pop in both native gather and recorded verify, while generic Cell reads retain their existing uncached pop. This is an internal semantic correction; generated code continues to call the existing public CounterSlot methods, so public ABI remains 37. Do not overload `Coerce` or silently reinterpret a schema-12 expression.

### Guards and acceptance

1. A pure source probe verifies low/high byte placement against an independent TypeScript capture, including zero and a value above 255. Negative renderer tests reject non-Field operands and any unknown IR length/variant.
2. A stateful probe verifies `Counter.read() as Field as Bytes<32>` with native result, state and per-query gas against TypeScript. If it becomes recordable, compare ordered VM/private outputs/replay and run the pinned ZKIR proof plus ledger validation/application.
3. Compile the exact original bboard source and report the next blocker precisely. Do not count any of its exports as assessed until compiler metadata exists for the complete source.
4. Keep all generated fixtures fresh, run targeted and full renderer tests, verify compiler target smoke selectors for the new probe, and record an exact inventory receipt. A source-level negative check must continue to reject unsupported byte widths rather than truncate.
5. Conventional GPG-signed/DCO local commit; no push or remote CI.
