## Historical decision and amendments

### Problem and source evidence

At exact integrated `0eeae0b7`, `examples/rust_backend/pure_call_action.compact::save` is proof-required but recording stops at `StateAction::PureCall(require_positive)`. The callee has one Field parameter and a pure `Sequence` body with a single `Assert(value != 0)` followed by Unit. `examples/rust_backend/assert_parity_oracle.compact::trigger_ok` and `trigger_fail` stop at Boolean `StateAction::Let` binding a call to `require_true`, a one-Boolean pure `Sequence` with `Assert(b)` followed by return `b`. Native Rust already calls the generated pure circuit with `?`, so failure returns `CompactError::AssertionFailed` before a ledger write. The recorded emitter cannot yet retain those narrow pure assertion calls.

The original `test-center/test-contracts/welcome.compact` still rejects source compilation at constructor line 36 (`Rust constructor fold needs a literal iterable`) on this exact branch. It cannot be counted as an Assert capability gain here; ADR-0112 is a prerequisite and Welcome requires a later exact source audit.

### Before and after generated Rust

Before, native `save` uses `crate::pure_circuits::require_positive(value)?` then writes `stored`, while `recorded::save` is absent. Native `trigger_ok/fail` call `require_true(constant)?` then write `flag`, while their recorded calls are absent. After, generated recorded Rust retains the typed pure call before any VM effect:

```rust
crate::pure_circuits::require_positive(value)?;
let frame = crate::ledger_slots::stored.record_write(frame, value)?;

let ok: bool = crate::pure_circuits::require_true(true)?;
let frame = crate::ledger_slots::flag.record_write(frame, ok)?;
```

`require_true(false)?` must return `AssertionFailed` before the `flag` write. The failing API may be generated and callable, but no successful proof or ledger application exists for that input.

### Decision and ownership

Admit only a compiler-typed pure call whose callee has one parameter and exactly one `Expr::Assert` in a pure `Expr::Sequence`; its condition is either the same Boolean parameter or a Field parameter compared with literal zero, and its return is either Unit or that Boolean parameter. Lower a Unit callee at `StateAction::PureCall` and a Boolean callee at an immediately bound `StateAction::Let`. Require a pure, typed argument available from a parameter/local/literal. Emit a call to the generated pure Rust function with `?` so existing pure circuit assertion behavior and message own the failure. Preserve current `RecordingFrame` order; no VM operation is generated by the pure call. Arbitrary pure calls, extra assertion steps, stateful/witness arguments and other return types remain unsupported. Reuse schema-11 IR, AST emitter, `CompactError`, runtime recording, ledger-8 VM and gas ownership. No runtime API or schema change.

### Acceptance and limits

Capture fresh TypeScript executions for `save(7)`, `save(0)`, `trigger_ok`, and `trigger_fail`; compare generated native and recorded success state/result, four gas dimensions, ordered public VM, private outputs and Verify replay. For the two expected failures, compare error type/message and assert no ledger write or public/private effect. Pinned ZKIR 2.1.0 must prove and ledger-apply successful `save(7)` and `trigger_ok`; `trigger_fail` and `save(0)` are negative-path capability checks, not successful proof cases. Add a negative renderer guard for nonassert or effectful pure calls. Check exact inventory gain with unchanged denominator, focused local gates, fixture snapshots, rustfmt and Clippy. No user-facing documentation edit, push or remote CI.
