# AGENT.md — Working in the compact repo as an LLM

This file is the contract between LLM-driven contributors (Claude, Copilot, Cursor, Codex, and their descendants) and this repository. Every automated agent MUST read this file before touching code, opening a PR, or interacting with CI.

Human contributors should also read it — it captures the constraints CI enforces and the pitfalls that recur.

## 1. Repository shape

**compact** is the Compact language toolchain. This fork adds a Rust codegen target (`compactc --rust`).

- `compiler/` — Chez Scheme sources. `rust-passes-*.ss` are the Rust codegen (7 modules, ~9 kLOC).
- `runtime-rs/` + `runtime-rs-macros/` — the `compact-runtime` Rust crate that generated `lib.rs` files depend on.
- `tests-e2e-rust/` — byte-parity test corpus. 25+ fixture crates + integration tests.
- `examples/` — canonical `.compact` sources exercised by the fixtures.
- `.github/workflows/` — CI. Six workflows; the relevant ones for LLM work are covered in §6.
- `third_party/` — path-mounted deps materialised by `nix develop`. **Not present on a bare checkout.**

Branch on this fork: `codegen-rust` is where all Rust codegen work lives. `main` mirrors LFDT-Minokawa upstream. Feature branches (`passport-contract`, `feature/*`) target `codegen-rust`, not `main`.

## 2. Non-negotiable rules

Break any of these and you will fail CI or corrupt the audit trail.

1. **All commits are GPG-signed AND DCO-signed-off.** Use `git commit -S -s`. Not one or the other; both. Never `--no-verify` or `--no-gpg-sign`.
2. **All work happens inside `nix develop`.** Bare `cargo` at a fresh checkout fails immediately at `cargo metadata` because the workspace path-mounts crates from `third_party/`. The devshell's `shellHook` materialises those symlinks. If you can't or won't use Nix, you can't build this repo.
3. **rustfmt is applied by nix's rustc, not your host's.** `.rustfmt.toml` enables nightly-only options (`imports_granularity`, `group_imports`, `format_code_in_doc_comments`). Host stable rustfmt silently ignores them and produces different output. Always fmt via `nix develop --command cargo fmt`.
4. **Never edit `tests-e2e-rust/contracts/*/lib.rs` by hand.** Those files are regenerated by `compactc --rust`. The `codegen_regression` test asserts they are byte-identical to emitter output. To modify a fixture's generated code, change the `.compact` source or the emitter passes, then regen.
5. **Never push to `upstream` (LFDT-Minokawa/compact).** This fork's `remote.upstream.pushurl` is set to `DISABLED` deliberately. All PRs stay on `yshyn-iohk/compact` per repo policy.
6. **Never file an upstream PR without explicit human authorization in the current session.** Prior upstream submissions ([#472](https://github.com/LFDT-Minokawa/compact/pull/472), [#542](https://github.com/LFDT-Minokawa/compact/pull/542)) were closed by the owner. Don't retry unprompted.

## 3. The three CI gates that must pass

Every PR to `codegen-rust` (or any base branch on this fork) must clear:

### 3.1 Format + Clippy (`.github/workflows/rust-runtime-test.yml`)

Runs `cargo fmt --check` + `cargo clippy -- -D warnings` under `nix develop`. Common trip-ups:

- Local stable rustfmt output diverges from nix's nightly rustfmt. If CI fails on `Diff in .../file.rs:N`, run `nix develop --command cargo fmt` locally, commit the resulting diff.
- Clippy's `incompatible_msrv` fires on stdlib methods newer than the crate's declared MSRV (currently Rust 1.85 for `compact-runtime`). Prefer the older idiom (`% 2 != 0` over `.is_multiple_of(2)`) instead of bumping MSRV.
- Clippy's `should_implement_trait` on a method whose name shadows a std trait: add `#[allow(clippy::should_implement_trait)]` with a comment explaining why the name is load-bearing (usually: codegen emits against it).

### 3.2 Changelog Check (`.github/workflows/changelog-check.yml`)

Requires **both** on every PR:

1. `CHANGELOG.md` in the diff.
2. `compiler/compiler-version.ss` in the diff (the `(make-version 'compiler X Y Z)` triple bumped).

The version bump also has to update `flake.nix`'s `packages.compactc.version = "X.Y.Z"` (there's an `NB:` comment in `compiler-version.ss` calling this out).

The check accepts a `skip-changelog` label as an escape hatch for typo fixes / internal refactors / CI-only changes — only a repo maintainer can apply the label.

### 3.3 Runtime + e2e tests

`cargo test -p compact-runtime -p tests-e2e-rust`. Includes `codegen_regression` which regenerates every fixture's `lib.rs` under the current compactc and asserts byte-identity. **Any codegen change requires the fixtures to be regenerated in the same commit.**

## 4. Historically-flaky checks you can safely ignore

These fail on the fork because of infra issues (missing IOG Nix cache secrets), not code:

- **Compiler Build / Build and test compiler** — the vscode-extension Nix derivation (`compact-vscode-extension-0.2.11.drv`) can't fetch its NPM deps without the IOG cache. Upstream main runs this workflow green on schedule; the fork's own PRs consistently red on this job for ~a year. Not a code failure. If you touched `editor-support/vsc/`, that's different — investigate. If you didn't, ignore.

## 5. Standard workflows (agent-friendly recipes)

### 5.1 Add or change a fixture

1. Edit `examples/<name>.compact` (or add a new file).
2. Regenerate the fixture crate:
   ```bash
   nix build .#compactc
   result/bin/compactc --rust --skip-zk --skip-ts examples/<name>.compact tests-e2e-rust/contracts/<name>/
   ```
3. If it's a new fixture, register it in `tests-e2e-rust/Cargo.toml` (workspace members) and `tests-e2e-rust/tests/codegen_regression.rs` (FIXTURES list).
4. Capture the TS reference bytes — mirror the pattern used by an existing similarly-shaped fixture. The capture script lives under `tests-e2e-rust/fixtures/` or is named `capture-<name>.mjs`.
5. Write the Rust byte-parity test at `tests-e2e-rust/tests/<name>.rs` (constructor → each circuit → assert `ContractState::serialize()` byte-equals the TS reference at every step).
6. Quality gate: `nix develop --command cargo fmt --all` then `nix develop --command cargo test -p tests-e2e-rust`.
7. Bump `compiler/compiler-version.ss` + `flake.nix` + add CHANGELOG entry (see §3.2).

### 5.2 Change the codegen (walker or emitter passes)

1. Edit `compiler/rust-passes-*.ss`.
2. `nix build .#compactc` to rebuild the compiler.
3. **Regenerate every affected fixture** — run the regen step from §5.1 for each. Or use `just codegen` if a target exists.
4. Inspect the diff: `git diff tests-e2e-rust/contracts/`. Categorise each change:
   - Expected shape change (e.g. new op added, `.popeq` cached-flag corrected) — commit as-is.
   - Unexpected shape change (e.g. previously-emitted code disappears, a type-check error appears) — **STOP**. Your codegen change has an unintended consequence. Fix before regenerating.
5. `nix develop --command cargo test -p tests-e2e-rust`. Both per-fixture byte-parity tests AND `codegen_regression` must be green.
6. Version bump + CHANGELOG (§3.2).
7. `git commit -S -s` (walker/emit changes + regenerated fixtures in the same commit or a paired commit — commit granularity matches the change's logical shape).

### 5.3 The correctness gate you should routinely exercise

`codegen_regression` is not just a hygiene check. Byte-parity via `ContractState::serialize()` is structurally blind to source-level codegen drift (bugs that change generated Rust without changing serialised state — Bug-8, Bug-9, Bug-10 all hid this way and were only surfaced by running the full regen sweep). When investigating any codegen-adjacent question, run:

```bash
nix develop --command cargo test -p tests-e2e-rust --test codegen_regression
```

If it fails, **classify every diff hunk** before mass-regenerating. See `docs/superpowers/notes/` for prior investigations of this pattern.

## 6. Commit hygiene

- Body wraps ~72 chars.
- Subject: `<scope>: <lowercase imperative>` (e.g. `rust-passes: A20 — read-no-arg adt-op vm-code lowering`, `chore(fmt): apply nix-shipped rustfmt`, `tests-e2e-rust: bug11_fixture byte-parity`).
- Explain the **why**, not the what. Diff already shows the what.
- Cite prior commits with short hashes when a change follows or fixes an earlier one.
- Every commit must be `git commit -S -s` per §2.1. Verify with `git log --format="%h %G? %s" -1` — the second column is `G` on success, `B` (bad) or `N` (none) on failure.
- Co-author trailer for LLM-assisted commits:
  ```
  Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
  ```
  (or the equivalent for your assistant). **Do NOT** add `Signed-off-by:` manually — the `-s` flag adds it.
