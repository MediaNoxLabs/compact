## 1. What this milestone delivers

The Rust backend turns the compiler's private typed IR into structured Rust syntax using `syn`, `quote`, `proc-macro2` and `prettyplease`.
This milestone improves domain ownership, generated API quality, checked primitives, focused derives and a reusable contract testkit.
It adopts the selected DID and digital-passport sources, adds meaningful behavior/coverage evidence, and records independently reviewed fixes.
It also retains measured alternatives that were rejected or deferred, instead of treating smaller generated source as automatic improvement.

The runtime reuses official ledger8/zk domains, VM operations, serialization and proof interfaces.
It does not introduce another VM or replace the upstream cryptographic semantics.
Native execution, recording/replay, proving/application and network observations remain separate evidence tiers.

## 3. Domain and component model

```text
Compact source and imports
  -> existing frontend typing and lowering
  -> private Rust IR20: declared identities, values and source context
  -> checked admission: not applicable / rejected / admitted
  -> native Rust emission + optional checked recorded effect plan
  -> Rust syntax tree and formatted generated crate
  -> runtime adapters over official ledger8/zk primitives
  -> native result | VM replay | proof/application | network observation
```

| Owner | Responsibility | Boundary engineers should preserve |
|---|---|---|
| Frontend | Source typing, source diagnostics and ledger operation definitions | Private IR is not a public Compact schema |
| Backend naming/value owners | Rust names, type mappings and checked value lowering | No raw-name collision or silent bound reinterpretation |
| Stateful emitter | Native calls, witnesses and ordered effects | Preserve short circuit, errors and witness order |
| Recorded planner | Whole admitted effect plans and typed operands | A rejected subplan cannot become an accepted partial trace |
| Runtime | Checked values, typed ledger paths, execution/recording adapters | Official VM/codec/crypto semantics remain upstream-owned |
| Transaction adapters | Explicit offer policy, key/address/state/input binding | Local consistency is not authenticated chain provenance |
| ContractLab / ProofLab | Scenario checkpoints / official local proof-provider setup | Execution, replay, checking, proving and finality stay distinct |

Navigation starts at [backend assembly](../../tools/compact-rust-backend/src/lib.rs),
[value lowering](../../tools/compact-rust-backend/src/value_lowering.rs),
[native facade](../../tools/compact-rust-backend/src/stateful/facade.rs),
and [recorded composition](../../tools/compact-rust-backend/src/recorded/typed_plan/composition.rs).
Ownership extractions reduced mixed responsibilities in `lib.rs`, `stateful.rs` and `recorded.rs`; no claim that every large match is eliminated follows.

## 4. Generated APIs and engineering decisions

Generated crates keep typed public circuit calls, source-linked names, witness interfaces and runtime representations.
Mechanical derives own representation boilerplate; ordinary Rust functions retain semantic and VM work.
Focused helper consolidation was accepted after source/effect equivalence checks.
Generated argument records were explored but default promotion remains deferred; `Rc`/binding-ID alternatives did not justify their cost.
No public “high/low abstraction level” switch or circuit-body macro DSL is promised by this milestone.

Compile-fail controls demonstrate concrete boundaries: reused moved context fails with E0382; unchecked bounded-value construction fails with E0423.
Positive controls perform real generated calls and test exact checked-bound outcomes.
These guarantees complement runtime authority/codec checks; ownership is not deep isolation or authenticated identity.

### Explicit decoding policy

```rust
// API sketch: imports and material acquisition are omitted.
let limit = EncodedSizeLimit::default(); // opt-in 64 MiB encoded-byte policy
let key = decode_verifier_key_with_limit(bytes, limit)?;
// EncodedSizeLimit::new(application_limit) supplies an explicit override.
```

The [decoder implementation](../../runtime-rs/src/transaction/decoding.rs) checks admission before upstream decoding.
Legacy APIs retain their behavior; a limited refusal does not silently retry through them.
The preset is observed compatibility headroom, not a protocol maximum or aggregate heap/CPU budget.

## 5. ContractLab and the optional ProofLab

[ContractLab](../../testkit-rs/src/lab.rs) runs generated native calls and recorded VM replay with explicit environment and typed witnesses.
It retains owned snapshots/forks, validates restore metadata, preserves committed checkpoints on failed calls and redacts private data by default.
External/shared witness effects are not rolled back; supplied artifact hashes are not authenticated provenance.
Execution gas is query-summed; replay gas is reported separately, and upstream query limits remain per query.

[ProofLab](../../testkit-rs/src/proof.rs) is an opt-in test fixture using official `Resolver`, `ParamsProverProvider` and `LocalProvingProvider`.
It adds no replacement provider trait or ledger-domain DTO.

```rust
// Illustrative excerpt from the compile-checked API example.
let lab = ProofLab::new(resolver, params);
let provider = lab.provider(rng);
let skip_sequence = provider.check(&preimage).await?;
// Separate operation; consumes the official provider:
let proof = provider.prove(&preimage, None).await?;
```

The new fixture tests exercise genuine assertion checking, missing/malformed material, provider errors and refused proof attempts.
They do not claim successful proof generation, network submission or production client orchestration.
The broader client/provider problem remains CoPS-002/#496; the delivered runner is the bounded #497 slice.

Internal/source audit acceptance and independent external **coding-agent** reviews remain distinct from human security certification.
