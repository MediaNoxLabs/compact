## Refresh procedure

1. Select a new signed prototype checkpoint; do not read claims from a dirty
   worktree as delivered state.
2. Read the latest 0.4 dashboard, EA13 closure report, ADR index, CoPS register
   and evidence-reuse matrix.
3. Update the cutoff table in `README.md` and `site/.../data.js`.
4. Update only claims whose exact source/evidence premises changed.
5. Run `python3 site/rust-ast-storybook/package.py`.
6. Run `python3 site/rust-ast-storybook/check.py`.
7. Preview locally and test keyboard navigation, reduced-motion mode and mobile
   widths.
8. Review `ambiguities.md`; close an item only with a public or publishable
   evidence reference.

## Publication boundary

The artifact is prepared for GitHub Pages but not deployed. No workflow is
added. A maintainer can push `rust-ast-docs` and select that branch's `/docs`
directory under **Deploy from a branch**, using the instructions in the site
README. This keeps the documentation out of `codex/rust-backend-ast` until the
review window ends.
