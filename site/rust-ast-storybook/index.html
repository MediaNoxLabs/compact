Private state, upstream query context, Zswap intents, cost model, per-query gas guard and optional execution key.

Not a trace or transaction.
RESULT

Successor context, typed source result, summed query cost and ordered private FAB outputs.

RECORDING

Runs admitted operations while retaining ordered public Verify instructions and sealed identities.

Native support does not imply this exists.
OBSERVATION

ObservedContractState

Address, public state and caller-supplied transaction/block metadata with explicit allocation policy.

Observation is not finality proof.
CALL BINDING

RecordedCall

Ties trace, entry point and typed FAB input to the exact state from which recording began.

Still checks verifier and replay.
SHIELDED INTENT

Source-ordered inputs/outputs with provisional or authoritative offer-bound allocation.

Not wallet state or a validated offer.

DIAGRAM B · EVIDENCE FLOW

A value reaches the ledger through six different claims

  1. 01Generatetypes · slots · circuit fncompiler + Rust AST
  2. 02ExecuteCircuitResultnative semantics + observed gas
  3. 03RecordRecordedCircuitResultexecution + ordered PublicTrace
  4. 04PrepareContractCallPrototypeobserved state + verifier + replay
  5. 05ProveProofPreimage → proofprovider / ZKIR / proving parameters
  6. 06ApplyIntent → Transactionledger validation and state transition

Generated Rust owns steps 01–03 and the typed entry into 04. Proving and application remain explicit consumer/testkit operations so a native method can never masquerade as proof or ledger evidence.

Macros do not decide circuit control flow, disclosure, ledger paths, recording admission, gas policy or proof support. Those decisions remain visible in the frontend, typed backend and runtime.
